
# Template Method 模板模式

#### 问
在介绍template method这种设计模式中，有下面一段话，请举例详细解释。使用父类类型的变量保存子类实例的优点是，即使没有用 instanceof 等指定子类的种类，程序也能正常工作。

无论在父类类型的变量中保存哪个子类的实例，程序都可以正常工作，这种原则称为里氏替换原则 2（The Liskov Substitution Principle，LSP）。当然，LSP 并非仅限于 Template Method 模式，它是通用的继承原则。

### GPT答
在面向对象编程中，模板方法模式（Template Method Pattern）是一种行为型设计模式，它定义了一个操作中的算法框架，将某些步骤延迟到子类中。父类在模板方法中定义算法的结构，而子类则实现具体的步骤。

里氏替换原则（Liskov Substitution Principle, LSP），LSP 是面向对象设计的一个基本原则。它指出，在程序中如果使用的是父类的对象，那么替换成子类的对象，程序的行为应该保持不变。这意味着子类可以替换父类，而不影响程序的正确性。

#### 示例

假设我们有一个模板方法模式的实现，用于制作饮料：

```java
abstract class Beverage {
    // Template method
    public final void makeBeverage() {
        boilWater();
        brew();
        pourInCup();
        addCondiments();
    }

    protected abstract void brew();
    protected abstract void addCondiments();

    private void boilWater() {
        System.out.println("Boiling water");
    }

    private void pourInCup() {
        System.out.println("Pouring into cup");
    }
}

class Tea extends Beverage {
    @Override
    protected void brew() {
        System.out.println("Steeping the tea");
    }

    @Override
    protected void addCondiments() {
        System.out.println("Adding lemon");
    }
}

class Coffee extends Beverage {
    @Override
    protected void brew() {
        System.out.println("Dripping coffee through filter");
    }

    @Override
    protected void addCondiments() {
        System.out.println("Adding sugar and milk");
    }
}
```

使用父类类型的变量

```java
public class BeverageTest {
    public static void main(String[] args) {
        Beverage myTea = new Tea();
        Beverage myCoffee = new Coffee();

        myTea.makeBeverage();
        myCoffee.makeBeverage();
    }
}
```

#### 解释

1. 父类类型的变量：
   - `myTea` 和 `myCoffee` 都是 `Beverage` 类型的变量，但分别保存了 `Tea` 和 `Coffee` 的实例。
   - 这体现了多态性。无论 `myTea` 和 `myCoffee` 是 `Tea` 还是 `Coffee` 的实例，程序调用 `makeBeverage()` 方法时，都能正常执行。

2. 遵循 LSP：
   - 可以在不改变 `BeverageTest` 类的情况下，轻松替换 `Tea` 或 `Coffee` 为其他 `Beverage` 子类。
   - 例如，如果有一个新类 `HerbalTea` 继承自 `Beverage`，并实现了 `brew()` 和 `addCondiments()`，可以直接使用 `Beverage myDrink = new HerbalTea();`，程序仍然可以正常工作。

#### 优点

- 灵活性：可以在运行时决定使用哪个子类，而无需修改现有代码。
- 可扩展性：添加新的子类时，不需要更改现有的代码结构，只需实现抽象方法。
- 代码复用：通过父类中定义的模板方法，避免了重复代码。

这种设计符合里氏替换原则，使得代码更加健壮、易于维护和扩展。

# Singleton 单例模式

```
public class Role {
    private static final Role sInstance = new Role();
    private Role() {}
    public static Role getInstance() {
        return sInstance;
    }
}
```
由于Role的构造函数私有化，因此Role的实例不能通过new创建，只能通过Role.getInstance()获取，而且该实例是在类加载的时候就已经创建了，因此得名饿汉单例模式，非常形象。那么什么时候类被加载呢？以下三种情况：

- 生成该类对象的时候，会加载该类及该类的所有父类
- **访问该类的静态成员的时候**(即调用getInstance方法时)
- class.forName(“类名”)

# Flyweight 模式
Flyweight模式是一种结构型设计模式，旨在通过共享尽可能多的相同对象来有效地支持大量的细粒度对象，从而减少内存使用和提高性能。它特别适合在系统中存在大量相似对象的场景。
#### Intrinsic和Extrinsic
Flyweight的关键是设计功能到底是共享还是独占。
Intrinsic信息：本质的，是被共享的信息，不论什么情况下都不会被改变，不依赖于实例状态。
Extrinsic信息：外在的，不能被共享，依赖于实例的状态。

共享信息，"修改一个地方会对多个地方产生影响"，这样所有信息都相同。而如果把这个信息改为不能被共享的信息，则每一个示例会有具体的值。哪些信息应该被共享，应该取决于具体的业务场景。
